# Frontend Implementation Plan (Ask Surfaces Phases B+C: widget + playground)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The embeddable ask-widget (`widget.js`, Shadow DOM IIFE) and the playground SPA that consumes the same React component, per the approved mockups.

**Architecture:** One `frontend/` Vite + React + TS workspace, two build modes (`vite build` for the SPA, `vite build --mode widget` for the IIFE). The widget panel is a pure component driven by a `useAsk` state machine; the embed bootstrap mounts it in a shadow root; the playground renders it inline. Tokens are CSS variables; theme = a class on the root (shadow root or document).

**Tech Stack:** Vite 5, React 18, TypeScript, Tailwind (shadow-scoped), vitest + @testing-library/react, lucide-react (playground only).

**Spec:** `docs/superpowers/specs/2026-09-01-ask-surfaces-design.md`
**Visual authority:** the committed mockups in `design/*.dc.html` — copy exact colors, sizes, spacing, and copy text from them; the token table in Task 1 is extracted from those files. Do not invent values.

## Global Constraints

- The widget bundle: React bundled in, IIFE, Shadow-DOM-mounted, NO lucide-react/framer-motion/network fonts by default; gzip ceiling 60KB (budget 50 + slack) enforced in Task 7.
- Fixed accent `#6366F1`; palettes exactly as Task 1's token table (extracted from the approved mockups). Icons: inline SVG in the widget; lucide-react allowed in playground chrome only.
- The widget never owns a theme toggle — `data-theme` light|dark|auto only. The playground's toggle is the ayushmxxn CSS variant with the four fixes (ThemeProvider wiring, keyboard, aria-pressed+label, ≥44px hit area, token colors).
- A11y: ⌘K/ctrl+K open, ↑↓ navigate, ⏎ ask, esc close, focus trap, `aria-live="polite"`, `prefers-reduced-motion` respected, 44px targets.
- Copy is literal from the mockups ("RAN THIS EXACT QUERY", "validated by your server", "Nothing in your schema answers this", "refused to guess · 0 queries run", "Answers only from your schema — it refuses to guess.").
- All frontend commands run in `frontend/`; gate before each commit: `npm run lint && npm run test -- --run && npm run build && npm run build:widget`.
- No AI attribution in commits.

### Task 3: API client + useAsk state machine

**Files:**
- Create: `frontend/src/lib/api.ts`, `frontend/src/lib/useAsk.ts`
- Test: `frontend/src/lib/useAsk.test.ts`

**Interfaces:**
- Consumes: serve-layer contracts (spec table): `POST {api}/api/search` → `{outcome, backend, query, result, reason, schema_used, attempts, elapsed_ms}`; `GET {api}/api/schema?query=&limit=`; `GET {api}/api/status`.
- Produces:
  - `createClient({api, token?}) -> {search(question, backend?), schema(query?, limit?), status()}` — fetch wrappers; token adds `Authorization: Bearer`.
  - `useAsk(client, backend?) -> {state, ask(question), reset}` where `state` is a discriminated union: `{kind:'idle'} | {kind:'thinking', stage: 0|1|2|3} | {kind:'answered', answer} | {kind:'abstained', answer} | {kind:'failed', answer|error}`. Thinking stages advance on a timer (600ms/stage, capped at stage 2 until the response lands — never fake 'execute' as done), snap to truth on arrival; timer respects `prefers-reduced-motion` (jump straight to stage 1 static). Network failure → `failed` with a plain message.

- [ ] **Step 1: Failing tests** (mock `fetch` with `vi.stubGlobal`)

```ts
import { renderHook, act, waitFor } from '@testing-library/react'
import { vi } from 'vitest'
import { createClient } from './api'
import { useAsk } from './useAsk'

const answered = { outcome: 'answered', backend: 'prometheus', query: 'up', result: [],
  reason: '', schema_used: ['up'], attempts: 1, elapsed_ms: 900 }

function mockFetch(payload: unknown, ok = true) {
  vi.stubGlobal('fetch', vi.fn(async () => ({ ok, status: ok ? 200 : 500, json: async () => payload })))
}

test('search posts question and bearer', async () => {
  mockFetch(answered)
  const client = createClient({ api: 'http://x', token: 't1' })
  await client.search('q')
  const [url, init] = (fetch as ReturnType<typeof vi.fn>).mock.calls[0]
  expect(url).toBe('http://x/api/search')
  expect(init.headers.Authorization).toBe('Bearer t1')
})

test('ask walks thinking then snaps to answered', async () => {
  mockFetch(answered)
  const { result } = renderHook(() => useAsk(createClient({ api: 'http://x' })))
  act(() => { result.current.ask('q') })
  expect(result.current.state.kind).toBe('thinking')
  await waitFor(() => expect(result.current.state.kind).toBe('answered'))
})

test('abstained outcome maps to abstained state', async () => {
  mockFetch({ ...answered, outcome: 'abstained', reason: 'nothing matches' })
  const { result } = renderHook(() => useAsk(createClient({ api: 'http://x' })))
  act(() => { result.current.ask('q') })
  await waitFor(() => expect(result.current.state.kind).toBe('abstained'))
})

test('network error maps to failed', async () => {
  vi.stubGlobal('fetch', vi.fn(async () => { throw new Error('down') }))
  const { result } = renderHook(() => useAsk(createClient({ api: 'http://x' })))
  act(() => { result.current.ask('q') })
  await waitFor(() => expect(result.current.state.kind).toBe('failed'))
```
